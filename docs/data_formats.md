# Data contracts

## Skill library

JSONL, one skill per row. Minimal retrieval card:

```json
{"id":"skill::inspect","layer":"procedural","text":"Inspect the required fields before updating an object.","apis":["objects.inspect"]}
```

A structured record with `skill_id`, `name`, `app`, `trigger`, `preconditions`, `procedure`, `failure_handling`, and `apis` is also accepted. Each `procedure` entry contains `step`, `what`, and optional `code`. `apis` provides the mapping from an executed operation to the next-step skill supervision target. Decision points with no matching skill are not supervised, but their evidence remains in the recurrent history.

SkillsBench cards may add `inject`: a compact name, purpose, and mounted `SKILL.md` path. Use portable mount paths. Declarative API cards can optionally join the scoring pool; they are never selected as procedural skills.

## Navigation trajectories

```json
{"task_id":"scenario_variant","scenario":"scenario","instruction":"Update an object","steps":[{"say":"Inspect first","code":"apis.objects.inspect()","env_in":"Initial observation"},{"say":"Update it","code":"apis.objects.update()","env_in":"Feedback from inspect"}]}
```

**`env_in` is the observation available before the code in that row is executed.** At decision t, the model reads only completed transitions preceding t; the current row's code supplies labels but never input history. Convert logs with post-action observations into this format explicitly. Terminal feedback has no next-action target.

## Projector corpus

An external benchmark harness and logging adapter must supply the teacher experiment directory; neither is included in this release. `work/teacher` is an input directory, not generated by the repository. The builder reads raw recorded calls at `tasks/<task_id>/logs/lm_calls.jsonl`, each with `input.messages` and `output.choices[0].message.content`, plus a JSON list of successful official-training task IDs. Already-injected requests are rejected. Output rows contain `task_id`, `messages`, `target`, `retrieved`, and `n_tokens`. A corresponding `.npy` contains raw encoder-space states of shape `(number_of_rows, 16, d_z)` in the same row order.

For history-compression pretraining, trajectory JSONL may additionally provide a scalar `trajectory_weight` and a per-decision `compression_probe` list. Both default to one and zero, respectively, when absent. Compression weights are configurable through the training CLI; see [implementation settings](paper_alignment.md).

The current corpus adapter is for AppWorld-shaped user-turn logs. Other benchmark adapters must preserve the same before-action timing, injection location and scenario-disjoint split. Raw benchmark trajectories are external inputs.

## Runtime history

Pass the full raw message history and a unique per-episode `lk` key, including a new key for each rerun. The request `model` string (`lk=<episode-id>::k=3::bud=1200`) carries proxy session controls, not the executor model ID. Missing or blank `lk` keys receive HTTP 400 before any state update. The executor's served ID is configured separately with `--upstream_model`.

With `INJECTION_ROLE=tool`, the SkillsBench adapter must include an existing injectable `tool` result on every request, including the initial decision. A request without this message receives HTTP 400 before state updates.

 AppWorld worked demonstrations are excluded using the actual-task marker. Assistant actions plus subsequent user/tool observations form transitions. The initial user observation supplies a generic task goal; adapters with different task layouts must supply the correct task statement. Do not feed previously injected blocks back into the proxy.
